01

Three stages, one frame

The camera is an extension of the scene, not a separate mode. Each frame runs all three stages in order, and the reticle on screen carries the verdict as it changes hands.

STAGE 1

Find

A person detector runs on the wide scene frame and gates everything after it. Cheap, and it means the expensive models never see a frame with nobody in it.

model yolov8n onnxruntime
STAGE 2

Check

A face detector runs inside each person box. Its output is measured against a pixel budget — face width, inter-ocular distance, and Laplacian sharpness — so a 14-pixel blur is refused rather than scored.

model SCRFD-500M
STAGE 3

Name

The face crop is embedded and compared by cosine similarity against the enrolled gallery. Above the calibrated threshold it gets a name and a confidence; below it, it stays anonymous on purpose.

model ArcFace MobileFaceNet

03

Build constraints

Stated up front, because a system that claims more than it can do is worse than one that tells you where its edges are.

Recognition is not identification

AstraGaze answers one question: does this face match a reference somebody enrolled? It does not answer who a stranger is, and a name only ever appears from the gallery.

  • No faces are enrolled from camera footage automatically
  • A name is never inferred from a name-like string
  • Below-threshold faces stay anonymous, by design

Accuracy depends on the reference

A gallery entry is one averaged vector built from 5–15 shots. The rig spec is explicit that one LinkedIn headshot will fail from the air, and our own audit agrees.

  • Frontal, ±30° yaw, slight down-pitch, sunglasses on/off
  • Thin identities are flagged rather than hidden
  • The threshold is reported with its measured error rates

Consent and retention

Enrolment is an explicit act by a named operator. The live path stores no video, no frames, and no new identities.

  • Nothing is written by a camera frame
  • Event logs hold names and timings, not images
  • Deployments in the US need a documented retention policy

Hardware

The whole pipeline runs CPU-only today, which keeps the hardware requirement to a standard server or a workstation.

  • onnxruntime, CPU execution provider
  • ~70 s cold start while models load
  • TensorRT FP-16 available on NVIDIA hardware
